# Git Workflow Documentation

## 1. Repository Initialization
Created a local Git repository using `git init`.

## 2. Main Branch
The main branch represents the stable version of the project.

## 3. Development Branch
The dev branch is used for development and integration.

## 4. Feature Branch
The feature branch is used to implement new changes separately.

## 5. Pull Requests
Pull Requests are used to review changes before merging branches.

## 6. Merge Conflict Resolution
Merge conflicts occur when Git cannot automatically combine changes. They are resolved by reviewing the conflicting files and selecting the correct content.

## 7. Git Tags
Git tags identify important versions of the project.

## 8. .gitignore
The .gitignore file prevents unnecessary files from being tracked by Git.

## 9. Feature Branch Development

A feature branch allows developers to work on new changes separately without directly modifying the main branch.

A feature branch was created to implement project changes independently. After completing the changes, developers commit their work and create a Pull Request for review before merging into the dev branch.

This approach keeps the main branch stable while new features are developed and reviewed.
