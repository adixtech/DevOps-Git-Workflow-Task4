# DevOps Git Workflow – Task 4

## Project Overview
This project is part of my DevOps Internship (Task 4). It demonstrates how Git and GitHub are used to manage a project using version control best practices.

## Objective
To understand and implement Git workflows, branching strategies, commits, pull requests, merging, conflict resolution, Git tags, and repository documentation.

## Tools Used
- Git
- GitHub
- Visual Studio Code
- Windows PowerShell

## Git Branching Strategy

This project uses three branches:

- **main:** Contains the final stable project.
- **dev:** Used for development and integration.
- **feature:** Used to implement individual project changes.

## Tasks Implemented

1. Initialized a local Git repository.
2. Created and configured the main branch.
3. Created development and feature branches.
4. Practiced Git commits and branch management.
5. Pushed branches to GitHub.
6. Created Pull Requests and merged branches.
7. Practiced merge conflict resolution.
8. Configured `.gitignore`.
9. Created Git tags.
10. Documented the workflow using Markdown.

## Git Commands Used

| Command | Purpose |
|---|---|
| git init | Initialize repository |
| git status | Check repository status |
| git add | Stage files |
| git commit | Save changes |
| git branch | Manage branches |
| git switch | Switch branches |
| git merge | Merge branches |
| git push | Upload changes |
| git pull | Download changes |
| git stash | Temporarily save changes |
| git tag | Create version tags |

## Learning Outcome

Through this project, I practiced Git version control, branch management, collaboration using Pull Requests, conflict resolution, and maintaining project documentation.
